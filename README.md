# 一夜狼人杀 · 在线版

> 📦 源码仓库：https://github.com/sqswer/one-night-wolfkill

基于《一夜狼人杀指南》全部角色与桌游流程，打造的一款**零依赖、可联机**的网页版 App。
创建房间 → 分享邀请 → 3-7 人组队 → AI 语音播报员按「黄昏 + 夜晚」顺序引导行动 → 白天语音/文字发言 → 投票 → 准确展示胜负。

## 快速开始

```bash
cd 一夜狼人杀在线网页版
node server.js
# 浏览器打开 http://localhost:3000
```

- 房主在首页选**本局人数（3–7）**→ 点「创建房间」，把**房间号 / 邀请链接**发给好友（手机同 Wi-Fi 访问 `http://<电脑局域网IP>:3000`）。
- 好友点「加入房间」输入房间号即可（人数达上限不可再加）。
- 房主在大厅：4/5/6 人可**一键点选推荐阵容**（来自《4/5/6人版指南》，按难度三级折叠：🟢基础 / 🔵进阶 / 🔴挑战），也可点「自选角色阵容」**按扩展分组（基础→破晓→吸血鬼）用 ± 计数器勾选本局角色**（守夜人/狼人/村民/吸血鬼可多选，其余 1 张）；准备就绪后「开始游戏」。
- 「准备」与「取消（离开房间）」为两个独立按钮：准备后高亮显示已准备；取消即退回首页。
- 进房后点顶栏 🎙️ 按钮即可开启**房间实时语音连麦**（WebRTC P2P，音频不经服务器）。

> 无需 `npm install`，无需任何 API 密钥、无需联网即可游玩（语音为浏览器本地能力）。

## 角色头像风格

全部 33 个角色头像采用**统一日漫卡通风格**，与狼人、爪牙、预言家等核心角色保持一致的视觉语言：透明背景、半身头像、色彩明快、特征突出，确保手机小图也能一眼识别。新增/替换角色时，请沿用同一风格，避免不同生成模型混用导致画风割裂。

## 已实现功能

| 需求 | 实现 |
|---|---|
| 创建线上房间 | 房号制（6 位），房主可重开 |
| 发送邀请 | 一键复制「房间号 + 邀请链接」 |
| 组队游玩 | 创建时设定 **3–7 人上限**（达上限不可再加）；4/5/6 人提供专属**推荐阵容**一键点选（来自《4/5/6人版指南》，分 🟢基础/🔵进阶/🔴挑战 三级折叠共 **57 套**），亦可**自选角色**：按「基础→破晓→吸血鬼」分组用 ± 计数器勾选（守夜人×2、狼人×2、村民×3、吸血鬼×2 可重复，其余 1 张）；准备 / 取消（离房）分离，准备后高亮 |
| AI 播报员（语音引导） | 服务端按固定顺序推送阶段口令，客户端用 **SpeechSynthesis** 中文 TTS 朗读「黄昏/夜晚/白天」全流程，可开关 |
| 黄昏 + 夜晚顺序行动 | 严格按指南夜行总顺序唤醒各角色；吸血鬼扩展含独立「黄昏」阶段（标记/恐惧/认亲） |
| 白天发言 + 语音实时输入 | **Web Speech API** 语音识别转写（Chrome/Edge 最佳），也支持文字输入 |
| 🎙️ 房间实时语音连麦 | **WebRTC mesh（P2P）** 实现多人同时语音通话：服务器只做 SSE 信令转发（`type:'voice'` 的 join/leave/signal），音频在玩家浏览器间直连、**不经过服务器**；座位号小者发起 offer 防冲突、ICE 候选缓冲、夜晚/黄昏阶段自动静音防偷听。需 https 或 localhost 环境；仅 STUN 无 TURN，跨对称 NAT 可能连不通 |
| 发起投票 | 房主一键发起，全员同时投票；**可投怀疑对象，也可选「不投票（弃票）」**。若所有人都未投出有效票（全员弃票），则无人被放逐——纯狼局/史诗战等场景下对应好人或多阵营获胜，符合官方规则 |
| 🤖 机器人补位（单人可玩） | 房主在大厅「🤖 机器人补位」可「加 1 个」或「一键补齐到满员」。机器人**不发言、不参与语音**，但会**自动完成夜晚行动**与**投票放逐**；机器人保镖自动保护、机器人猎人被放逐时自动开枪。一个人即可完整体验黄昏→夜晚→白天→投票→结算全流程 |
| 结果准确无误 | 服务端统一结算：狼队/好人/皮匠/猎人/王子顺延/保镖保护/吸血鬼多阵营，出局身份与胜负精确计算 |
| 身份卡展示角色图 | 游戏界面玩家身份卡中，对应**角色图片显示在角色名称左侧**（横向排列），更直观 |

> **近期修复（2026-08-24）**：① 语音单通——已修复 WebRTC 单向无声（远端 `<audio>` 挂 DOM、`ontrack` 用裸 track 兜底、`getUserMedia` 竞态期间暂存 offer 待麦克风就绪后 flush、双向均 `muted=false`），两端均可互听；② AI 播报员 TTS——增加 `speechSynthesis.resume()` 唤醒 + 首次手势解锁 + 无中文语音时回退默认语音，确保实际出声。

- **吸血鬼扩展**：吸血鬼、伯爵、血奴（黄昏阶段）、牧师、神射手、小偷、小魔怪、丘比特、刺客（独立阵营，含「状态标记」子系统：吸血鬼/恐惧/清白/爱之/刺杀标记）

内置 **57 套阵容预设**，与《4/5/6人版指南》完全对应：

## 技术架构（为什么难度最低）

- **后端**：Node.js 内置 `http`，用 **Server-Sent Events (SSE)** 做服务端→客户端实时推送，用 `fetch(POST)` 做客户端→服务端指令。**零第三方依赖**，不用安装任何包、不用数据库。
- **前端**：纯 HTML/CSS/JS，手机优先响应式。
- **语音**：两层能力均用浏览器原生 API，**免密钥、免联网、免费用**。
  - *播报员 TTS + 玩家语音识别*：Web Speech API（`SpeechSynthesis` / `SpeechRecognition`）。
  - *房间实时连麦*：**WebRTC mesh（P2P 直连）**——`server.js` 只做 SSE 信令转发，音频流在浏览器之间直连，服务器零带宽压力；仅配公共 STUN（Google），无 TURN 中继。

相比微信小程序（需开发者账号/云函数）或带 SFU 连麦的方案，此方案可在任意装了 Node 的机器上 `node server.js` 直接跑，跨设备用浏览器即可游玩，最快落地。

## 部署（Bonto / 容器）

- 基础镜像必须是 **glibc**（`node:20-bookworm-slim`）：sherpa-onnx 的 linux 二进制是 glibc 的，alpine(musl) 跑不起来。
- `npm start` = `node server.js`。`npm start` 的 **prestart** 会先跑 `scripts/ensure-tts-onstart.js`：MeloTTS 已就绪则秒过不联网；缺失则自动用 ghproxy 镜像拉取（幂等，首次约 190MB），拉不到仅告警并降级 Piper 启动。**Bonto 每次重建/唤醒容器都会自愈**，无需手动重跑。本地有 `tts-bin/` 时同样直接跳过。
- 同步：Bonto 配置 Git 仓库，点 **pull from remote** 同步重启。沙箱无法 push，本地 `git push origin main` 后去 Bonto 点一下即可。

### TTS 引擎在 Bonto 上的持久化

`tts-bin/`（MeloTTS 约 160MB + Piper）**被 `.gitignore` 排除、不在镜像内**，且 **Bonto 没有持久卷配置**：它的持久化模型就是 git 工作目录，每次 `pull from remote` / 重建容器会按 git 快照重置文件系统，未跟踪的 `tts-bin/` 因此被清掉（实测 room=692620 那局 melo 丢失回退 Piper）。同时 GitHub 单文件 100MB 硬上限会拒掉 `model.onnx`（约 150MB），**「提交进 Git」也走不通**。

采用**启动自检+按需下载**（已落地）：
- `package.json` 的 `prestart` 跑 `scripts/ensure-tts-onstart.js`：检测 `tts-bin/sherpa-onnx-offline-tts` 与 `vits-melo-tts-zh_en/model.onnx`，缺失就调 `install_melo.js` 经 ghproxy 镜像拉取（幂等），拉不到仅告警并降级 Piper 启动（不阻断服务）。
- 效果：Bonto 每次重建/从休眠唤醒都会自愈拉回引擎，无需手动干预，也不把 190MB 塞进 git、不碰 100MB 限制。
- 本地有 `tts-bin/` 时直接跳过；本地想装：`npm run install:melo`。
- 仍可用 `scripts/bonto-download-tts.sh`（幂等、支持 `TTS_BIN_DIR`）在终端手动装，或 `TTS_PROVIDER=piper` 临时回退。

## 已知限制 / 后续可扩展

- **实时语音跨复杂网络**：当前仅配公共 STUN、无 TURN 中继，同一局域网/常见家庭网络可正常 P2P 连麦，但**对称型 NAT / 严格企业防火墙**两端可能连不通。需要 100% 覆盖时可自建 coturn 或接入免费 TURN。
- 语音识别依赖浏览器支持（Chrome/Edge 体验最佳；Safari/Firefox 部分支持，可降级为纯文字）。
- 房间数据存内存，服务器重启即清空（适合聚会一局制；如需持久化可接 SQLite）。
- 化身幽灵/阿尔法狼等复杂机制做了**简化实现**（查看/交换），未完全复刻实体版全部细节。
- 暂无「跨服公网匹配」，邀请需同一局域网。机器人补位已实现（见上表）。
