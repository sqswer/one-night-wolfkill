## 1. 产品现状与定位（事实基础）

### 1.1 我们手里有什么（差异化卖点）
| 维度 | 现状 | 推广价值 |
|---|---|---|
| 内容深度 | 内置 **33 个角色全图鉴 + 57 套官方阵容**（4/5/6 人版指南逐套对应） | 「最完整的一夜狼人杀规则库」可做成核心内容资产 |
| 零门槛 | **零安装、零依赖、浏览器打开即玩**；Bonto 公网 `worfkill.bonto.run` | 朋友聚会/远程开黑，发个链接就能开局，转化率极高 |
| 单人可玩 | **机器人补位**：一个人也能跑完黄昏→夜晚→白天→投票→结算 | 解决「想玩但凑不齐人」的最大痛点，降低首次体验门槛 |
| AI 主持 | 服务端 Piper TTS + 浏览器原生语音，**全流程语音引导** | 新手不卡流程，老手可关；是区别于微信小程序版的关键体验 |
| 实时连麦 | WebRTC P2P 房间语音，音频不经服务器 | 0 带宽成本，但**仅 STUN 无 TURN，跨复杂 NAT 可能连不通**（核心短板） |
| 短平快 | 一局约 10 分钟，比传统狼人杀轻量 | 适合碎片化、聚会、团建破冰场景 |

### 1.2 当前短板（决定打法边界）
1. **无公网匹配**：必须邀请好友（同房间），没有「随机匹配/快速开局」。获客靠**熟人裂变**，冷启动慢。
2. **连麦稳定性**：仅 STUN，远程/跨运营商连不通时只能退回文字。影响「远程聚会」卖点。
3. **无账号体系 / 无埋点**：不知道谁在玩、玩几局、从哪来。所有增长与营收决策目前是盲飞。
4. **无营收**：纯公益，服务器（Bonto/云）与后续 TURN/移动端成本无着落。

### 1.3 一句话定位
> **「发链接就能开局、一个人也能玩、AI 主持带你走完一夜」的全角色一夜狼人杀网页版。**

## 2. 目标与北极星指标

### 2.1 北极星指标（North Star）
**周活跃对局数（Weekly Active Games, WAG）** —— 比 DAU 更贴近「真实使用」，且天然包含拉新（开房）+ 留存（复玩）。

### 2.2 二级指标与分阶段目标
| 指标 | 定义 | P0（1 月后） | P1（3 月后） | P2（6 月后） |
|---|---|---|---|---|
| WAG（周活跃对局） | 自然周内完成 ≥1 完整对局的不同房间数 | 200 | 1,000 | 5,000 |
| 新房间周增 | 每周新建房间数 | 150 | 700 | 3,000 |
| 邀请转化率 | 收到链接后成功加入的比例 | 40% | 55% | 65% |
| 次日/7 日留存 | 建过房的用户回流比例 | — / 15% | 25% / 25% | 35% / 35% |
| 单人局占比 | 含机器人的对局占比（新手漏斗入口） | 30% | 25% | 20%（自然下降=熟人多） |
| 营收（月） | 打赏+募集+VIP | ¥300 | ¥2,000 | ¥10,000 |
| 付费率 | 月活玩家中付费占比 | 0.5% | 1.5% | 3% |

> 目标值为**内部基线假设**，首月复盘后按真实数据校准，禁止拍脑袋硬套。

## 4. 用户增长与留存优化（产品杠杆）

> 推广拉来的人，得靠产品接住。下面按「性价比」排序。

### 4.1 P0 —— 先把「盲飞」变「可见」（埋点，1 周内）
- 服务端 logger 记录：`新房间创建 / 对局完成 / 人数 / 来源 ref`（来源靠邀请链接带 `?ref=`）。
- 隐私友好：**不采个人信息**，只记聚合计数。
- 交付：一个 `/admin/stats`（或每日打印日志）看板，至少能看到 WAG 与来源分布。
- 负责人：你 ｜ 优先级 P0

### 4.2 P0 —— 战绩分享 + 邀请裂变（2 周内）
- 对局结束页新增「📤 分享战绩」：生成带**房间链接 + 项目名**的分享图（canvas 前端画，零后端）。
- 邀请链接带 `?ref=<roomCode>`，服务端统计转化。
- 负责人：你 ｜ 优先级 P0

### 4.3 P1 —— 公网「快速匹配」房间（1–2 月）
- 当前必须邀请；新增「快速匹配」：系统分配一个公开房间号，任何人可加入，满员即开局。
- 这是**冷启动最大杠杆**——降低「没人一起玩」的流失。
- 注意：需基础防滥用（房间人数上限、敏感词房名过滤）。
- 负责人：你 ｜ 优先级 P1

### 4.4 P1 —— 连麦稳定性（TURN 中继，按营收节奏上）
- 当前仅 STUN，远程连麦不稳。上 **coturn** 或免费 TURN，**首月先用「文字降级」兜底**（连不通自动提示切文字，不阻塞对局）。
- 稳定连麦可设为 **VIP 专享**（见 5.3），反向补贴成本。
- 负责人：你 ｜ 优先级 P1

### 4.5 P2 —— 留存钩子
- **图鉴收集成就**：已玩过角色打勾，集齐解锁彩蛋（零成本留存）。
- **每周推荐阵容轮播**：首页推「本周挑战阵容」，制造回访理由。
- **活动/赛季**：节日主题房（万圣节吸血鬼皮肤）、新角色上线周。
- 负责人：你 ｜ 优先级 P2

## 5. 营收体系设计（打赏 / 募集 / VIP）

> 原则：**先轻后重、合规优先、不伤免费体验**。免费玩家永远能完整玩；付费是「更好/更帅/更稳/更支持」。

### 5.1 打赏（一次性，P0 立刻可做）
- **通道**：接入 **爱发电（afdian.com）** 个人创作者的「赞助」功能（个体可开、提现到银行卡，合规最省心）；同步放微信/支付宝收款码图片。
- **入口**：游戏内「☕ 请开发者喝杯奶茶」按钮 → 弹层展示收款码/爱发电链接 + 文案「AI 主持员的电费、服务器月租，靠你续命」。
- **档位**：¥6 / ¥18 / ¥66 / 自定义。
- **合规**：明示为「自愿赞助」，与游戏结果无关、非赌博、非抽成。
- 负责人：你 ｜ 优先级 P0（1 周内上线，先放链接即可）

### 5.2 募集（目标制众筹，P0–P1）
- **用途透明**：服务器月费、TURN 中继、新角色开发、移动端 App。
- **通道**：爱发电「目标」功能，或在游戏内「🔧 项目进度」页展示当前募集目标 + 进度条（进度数据手动/API 同步）。
- **例子**：
  - 目标 A「服务器续命」¥300/月 —— 达标则公示已覆盖。
  - 目标 B「新角色开发 ×3」¥600 —— 达标后排期开发并 @ 赞助者。
  - 目标 C「TURN 稳定连麦」¥1,200/年 —— 达标即上线，VIP 可优先用。
- 负责人：你 ｜ 优先级 P0（与打赏同期）

### 5.3 VIP 会员（订阅制，P1–P2，需账号体系）
- **先决条件**：需先做 **4.1 埋点 + 轻量账号**（昵称 + 设备/邮箱登录，见 6.2）。
- **档位建议**（低价走量，参考同类小游戏）：
  - 月卡 **¥9.9** ｜ 季卡 **¥25** ｜ 年卡 **¥88**。
- **权益设计（不破坏免费体验）**：
  | 权益 | 免费 | VIP |
  |---|---|---|
  | 完整 33 角色 + 57 阵容 | ✅ | ✅ |
  | AI 主持语音 | ✅ | ✅（**额外音色/语速档**） |
  | 机器人补位 | ✅ | ✅（**可设 2 个以上/高级 AI 行为**） |
  | 房间人数上限 | 7 人 | **10 人**（团建友好） |
  | 房间主题/背景音乐 | 默认 | **自选皮肤/主题** |
  | 头像框/名牌 | 默认 | **限定头像框/动态名牌** |
  | 连麦稳定性 | STUN（不稳） | **TURN 中继优先（稳）** |
  | 战绩统计与导出 | — | ✅ |
  | 去广告承诺 | 永不广告 | 永不广告（卖点，非权益） |
- **支付通道（重要·合规）**：
  - 个人阶段：**爱发电月捐** 即可实现「类 VIP 订阅」，最稳，无需商户号。
  - 规模化后（月营收过 ¥3k 或想做应用内支付）：建议**注册个体工商户 + 微信支付商户号**，用服务端 `/api/pay/callback` 验签开通 VIP。Bonto 有公网域名可接收回调。
- **红线**：VIP **绝不**卖「影响胜负的概率/信息」，只卖体验与便利，守住桌游公平性。
- 负责人：你 ｜ 优先级 P1（埋点/账号后做）

### 5.4 营收落地顺序
```
P0：打赏链接 + 募集目标页（1 周，零开发成本，先有现金流）
  ↓
P1：轻量账号 + VIP 月捐（爱发电）上线（1–2 月）
  ↓
P2：应用内支付 + TURN 专享 + 限定皮肤（营收过阈值后）
```

## 6. 技术实现要点（贴着现有零依赖栈）

> 现状：Node 内置 http + SSE + 内存存储，无数据库、无第三方依赖。改造尽量**小步、可回滚**。

### 6.1 埋点（P0）
- 在 `server.js` 关键事件（`createRoom` / 对局 `finish`）追加计数，写入 `data/stats.json`（新增目录，gitignore）。
- 提供只读 `/admin/stats` 返回 JSON；本地 `curl` 即可看。

### 6.2 轻量账号（P1，为 VIP 铺垫）
- **最简方案**：`昵称 + 设备指纹（localStorage uuid）` 即游客账号；进阶加邮箱验证码。
- 存储：`data/users.json`（或 better-sqlite3，引入一个依赖）。VIP 状态字段 `vipUntil`。
- 登录态：签发一个简单 token（HMAC），不引第三方 auth 库。

### 6.3 支付与 VIP 开通（P2）
- 爱发电月捐阶段：手动/API 拉取赞助订单，匹配用户后写 `vipUntil`。
- 微信支付阶段：`/api/pay/notify` 接收回调 → 校验 → 写 `vipUntil` → 客户端轮询/订阅状态。

### 6.4 募集进度页（P0）
- 前端静态「项目进度」页，进度数字由你维护在 `public/` 配置或 `data/` 文件，无需实时接口。

### 6.5 原则
- **不引入重依赖**、不动现有游戏引擎；新功能走独立路由 `/api/pay`、`/admin/*`。
- 每次改动仍走「本地改 → 你 `git push` → Bonto 拉取」流程。

## 8. 复盘机制（可复盘的核心）

- **节奏**：双周小复盘（看指标 + 调动作），月度大复盘（看趋势 + 改路线图）。
- **模板**：见同目录 `复盘看板.md`，每次复盘填写并提交（可存本仓库 `运营/` 或单独记录）。
- **指标口径**：严格按第 2.2 节定义，避免「口径漂移」导致误判。
- **决策规则**：
  - 某渠道连续 2 个双周 **新房间周增 < 目标 50%** → 砍投入或换形式。
  - 单人局占比 **> 40% 且 7 日留存 < 10%** → 优先做「快速匹配」而非加内容。
  - 打赏月转化 **< 0.3%** → 先检查入口曝光与文案，不急着加权益。
- **红线**：不卖胜负概率；不接赌博/抽成类；用户隐私只采聚合计数。

## 9. 风险与待确认
1. **支付合规**：正式 VIP 订阅建议注册个体户 + 微信支付商户，个人收款做经营性有风险（已用爱发电过渡）。
2. **连麦 NAT**：TURN 是成本项，先用文字降级兜住体验，营收起量再上。
3. **Bonto 限制**：确认 Bonto 能否稳定接收支付回调（公网域名 + 自定义路由）；不能则支付走爱发电外部完成。
4. **账号体系**是 VIP 前必须补课，但会引入存储与安全问题，需评估成本。
